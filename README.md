# Подряди — 0.1.0

Отдельный, автономный MVP российского маркетплейса строительных и ремонтных работ. **Не использует базу Ultrabook**. Принципы ведомостей объёмов (ВОР) и тендерных предложений перенесены в упрощённую доменную модель. Рабочее название временное: перед регистрацией домена проверить товарные знаки.

## Реализовано

- Регистрация заказчиков и мастеров, вход/выход, PBKDF2-хеширование, HttpOnly-сеансы, CSRF для записи, лимит перебора паролей.
- Публичная лента заказов без контактов и адресов, фильтрация по городу/категории/поиску.
- Создание задания с фотографиями, городом, бюджетом, сроком, до 40 позиций ВОР.
- Фото: не более 5 на заказ, до 5 МБ, JPEG/PNG/WebP, сервер перекодирует в WebP, удаляя EXIF. Хранилище не публикуется как статическая папка.
- Бесплатные предложения исполнителей: сумма, дни, примечания, максимум одно на задание.
- Владелец видит сравнение цен и выбирает одного исполнителя; можно отменить выбор и снова открыть приём предложений с журналированием.
- Прогрессивный расчёт цены контакта с граничными проверками.
- **Получение контактов исполнителем закрыто** (HTTP 402 даже для выбранного). Реальный платёжный webhook ещё не подключён. Никаких тестовых оплат и фальшивой разблокировки.
- Мобильная версия, кабинеты ролей, тарифы, дорожная карта.

## Быстрый запуск локально

```bash
python -m venv .venv
source .venv/bin/activate  # Windows: .venv\\Scripts\\activate
pip install -r requirements.txt
uvicorn app.main:app --reload --host 127.0.0.1 --port 8000
```

Откройте `http://127.0.0.1:8000`.

## Тесты

```bash
pip install pytest httpx
pytest -q
```

## Публичный запуск: блокеры

1. **Не публиковать на иностранном сервере с реальными ПДн граждан РФ.** Настроить инфраструктуру в РФ и выполнить оценку требований 152-ФЗ, документировать политику обработки ПДн и сроки хранения.
2. Настроить HTTPS и `PODRYADI_COOKIE_SECURE=true`, резервирование SQLite и защищённое хранение данных. Для роста перейти на PostgreSQL с миграциями и репозиторием доступа к данным.
3. Подключить верификацию телефонов/почты, антиспам, очередь модерации и безопасное удаление персональных данных.
4. Реализовать платёжный провайдер и кассовую фискализацию. Подтверждение платежа возможно **только** через верифицированный серверный webhook с проверкой подписи, суммы, идентичности платежа, идемпотентности и привязки к выбранному предложению. На текущем этапе unlock всегда закрыт.
5. Добавить договор-оферту и юридические документы, предварительно проверить закон о платформенной экономике (РФ, 2026).
6. Отдельно протестировать безопасность загружаемых изображений, нагрузку, abuse cases и браузеры перед настоящим пилотом.

## Структура

- `app/main.py` — HTTP API, аутентификация и авторизация, бизнес-операции;
- `app/db.py` — SQL-схема и управление SQLite-транзакциями;
- `app/fees.py` — единая формула тарифа;
- `app/static/` — мобильный интерфейс, без тяжёлых клиентских зависимостей;
- `tests/` — серверные тесты.

## Контейнерный запуск

```bash
docker compose -f compose.example.yml up -d --build
```

Обязательно настроить HTTPS на обратном прокси и отдельные резервные копии тома `podryadi_data`. По умолчанию сервер слушает только localhost хоста, публичная публикация без подготовленной юридической/платёжной инфраструктуры не рекомендуется.

## Чего сейчас нет

Полноценного эквайринга/возвратов, SMS-верификации, модерации объявлений, независимых мобильных приложений и подтверждённых рейтингов. В прототипе нет вымышленных исполнителей и заказов. Сервер предназначен для локальной разработки и закрытого тестирования.
